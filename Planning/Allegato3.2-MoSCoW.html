Distribuzione dell'effort MVP su 302 giorni-persona (Must 229 · Should 57 · Could 16). Target DSDM di riferimento 60/20/20: il Must al 75,8% riflette la criticità di Game Engine e Real-Time; il Could contenuto al 5,3% riduce il rischio di scope creep.

Must Have

229 gg · 75,8%
Game Engine
  • Regole Maraffone, turni, anti-cheat, punteggi, Maraffa/Cricca, persistenza partita
Backend Server
  • Auth (registrazione, login JWT, ospite), stanze (crea/join/lobby), persistenza partita, statistiche base, API REST sicure e <200ms
Real-Time Communication
  • WebSocket + auth, eventi di gioco, broadcast selettivo, lag compensation, reconnect, chat in-game
Frontend Web
  • 6 schermate da mockup approvati, design system, multi-device mobile-first, caricamento <2s
Social & Infrastructure
  • Notifiche in-app "è il tuo turno"; server dedicato, Docker, CI/CD, PostgreSQL+backup, logging, monitoring, SSL, disaster recovery

Should Have

57 gg · 18,9%
Backend Server
  • Profilo personalizzabile, password recovery, sistema amicizie, presenza online, inviti diretti
Frontend Web
  • Accessibilità WCAG 2.1 AA, bundle optimization, microinterazioni e animazioni
Social & Community
  • Sistema amicizie, profili pubblici utenti
Infrastructure & DevOps
  • Redis caching, error tracking (Sentry), firewall/DDoS (Cloudflare), architettura scalabile

Could Have

16 gg · 5,3%
Backend
  • Statistiche avanzate (carta più giocata, ecc.)
Real-Time
  • Chat globale di lobby
Frontend
  • Modalità daltonici (palette alternativa)
Social
  • Classifica globale (top 100), classifica amici

Won't Have

Esclusi dall'MVP
  • App mobile nativa iOS/Android (budget insufficiente → web responsive)
  • Social login (Google/Facebook) → v1.1
  • Modalità single-player vs IA
  • Notifiche push
  • Emoji/reactions in chat
  • Tornei strutturati
